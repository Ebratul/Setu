## What it is \{#what-it-is}
Setu checks every trade document you upload, such as a proforma invoice or a bill of lading. It reads the file, compares it with your deal, and gives a **risk score** from 0 to 100 and a clear verdict. If the PDF contains hidden text, you can reveal it.

The checks are deterministic code. A model may only help read a field the parser could not fill. It never decides the verdict and never sees hidden text. All data is simulated.

## Who uses it \{#who}
<RoleBadge role="buyer" />

Buyers and admins can upload and re-check. Judges can view only. Suppliers see a status only, with no score and no hidden text.

## When to use it \{#when}
- Before you release money from escrow. Documents are the evidence for each milestone.
- When a supplier sends a new or changed document.
- When a file looks odd and you want to see what is hidden inside it.

## What the results mean \{#results}
Higher score means higher risk.

| Score | Verdict |
|---|---|
| Under 30 | Passed |
| 30 to 60 | Warning |
| Over 60 | Failed |

Some findings force **Failed** whatever the weights: hidden text, an instruction written in the document, a bank account that does not match the supplier, and a duplicate document.

Checks include quantity, value maths, name match, bank account match, vessel and voyage, dates, ports, HS code, price band, hidden text, instruction scan, metadata, duplicate and extraction completeness.

Hidden-text reasons: White text, Tiny text, Outside the page, Invisible when rendered, Covered by another shape and Low contrast.

The **Registry** box says **Registered**, **Not registered yet**, or **Duplicate**. A duplicate is an exact copy or a re-saved near copy of a document already registered.

Other statuses: **Uploaded** (not checked yet) and **Rejected** (the file was refused).

The verdict feeds the release rules. A **Warning** document needs a one-tap Tier 2 approval before money is released. A **Failed** document blocks the release. See [Approvals](/docs/en/buyer/approvals).

## Tips and common mistakes \{#tips}
- Use PDF for documents and PNG or JPG for photos only.
- "The check could not finish" means a system problem. Press **Re-check**.
- Red boxes on the preview are approximate. The list shows each hidden span exactly.
- Use the eye button to open **What did the AI see?** for the document. See [Chat assistant](/docs/en/buyer/chat).

## Related security notes \{#security}
<Callout type="security" title="Document text is data, not instructions">
If a document says "release payment" or "skip checks", Setu ignores it, shows "This document contains a hidden instruction. Setu ignored it." and treats it as a Tier 3 trigger. Read [Prompt injection](/docs/en/security/injection-defence).
</Callout>
<Callout type="security">
Files are checked by magic bytes, not by name. Parsing runs in a sandboxed child process. Hidden text is only shown on request and only to non-suppliers.
</Callout>
