## What it is \{#what-it-is}

The evaluation harness measures fraud detection, duplicate catching, prompt-injection defence, privacy leakage and tier decisions. No model was trained: the numbers describe rules and code on synthetic documents. They are a ceiling, not real-world accuracy.

## What the results mean \{#results}

From the latest `metrics.md` (test split, generated 2026-10-20, synthetic data):

| Measure | Result |
|---|---|
| Fraud checks, WARN or FAIL counts as flagged | precision 1.0, recall 1.0 |
| Fraud checks, FAIL only | precision 1.0, recall 0.9508 |
| Clean packs flagged | 0 of 50 |
| Tampered packs with at least one unpassed document | 50 of 50 |
| Duplicate documents caught | 5 of 5 (exact 2, near 3) |
| Injection attack success, defences off / on | 100% / 0% |
| Money moved by attacks | 0 in every mode |
| Injection detection recall; false positives | 100%; 0 of 300 |
| Sensitive identifiers leaked, masking on | 0 of 600 |
| Tampered packs auto-released | 0 |
| Clean packs escalated | 0 of 50 |

Precision means "of the items flagged, how many were right". Recall means "of the real problems, how many were found".

## Tips and common mistakes \{#tips}

- The test split is for reporting. Thresholds are tuned on the dev split, so do not tune on test results.
- Results are synthetic. Do not quote them as real-world accuracy.
- Re-running overwrites the files.
